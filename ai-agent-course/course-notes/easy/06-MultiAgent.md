# 6교시 · Multi-Agent — 쉬운 설명 버전

## 왜 AI를 여러 명으로 나누나

지금까지는 AI 하나가 도구도 다 쥐고, 질문도 다 받고, 답도 혼자 썼습니다. 그런데 AI가 한 번에 기억하고 처리할 수 있는 양은 정해져 있습니다. 포토샵에서 레이어와 히스토리가 너무 많이 쌓이면 파일이 무거워지고 렉이 걸리는 것처럼, AI도 도구가 많아지고 대화가 길어지면 **처리 한계에 부딪힙니다.**

## 팀처럼 나누기 — 디자인팀 조직도와 똑같다

이번 시간엔 AI를 세 역할로 나눕니다. 디자인 회사의 팀 구성과 놀랍도록 비슷합니다.

- **연구책임자 (아트디렉터)** — 무엇을 할지 정하고, 아래 두 역할에게 업무를 나눠 맡깁니다. 본인은 직접 조사하거나 실행하지 않습니다.
- **자료조사 연구원 (리서처)** — 어떤 방법으로 풀지 조사하고 설계합니다. 웹 검색 등을 담당하지만, 직접 계산하거나 코드를 짜진 않습니다.
- **실험수행 연구원 (실무 디자이너/개발자)** — 설계받은 대로 실제로 코드를 돌려서 결과물(수치)을 냅니다. 판단은 하지 않고, 실행만 합니다.

**규칙**: 두 실무 담당(리서처, 실행 담당)은 서로 직접 대화할 수 없습니다. 모든 소통은 아트디렉터(연구책임자)를 거칩니다 — 실제 팀 협업과 똑같죠.

## 나누는 데는 대가가 따른다

역할을 나누면 "전달"이 늘어납니다. 아트디렉터가 리서처에게 브리핑을 쓰고, 리서처가 결과를 보고하고, 다시 아트디렉터가 실행 담당에게 브리핑을 써야 하죠. **이 왕복 시간이 대가**입니다. 대신 얻는 것:

- 각자 맡은 일이 명확해서, 문제가 생겼을 때 **어디를 봐야 하는지 바로 알 수 있음**
- 새 역할이 필요하면 기존 팀원 건드리지 않고 **한 명만 추가**하면 됨 (기존 팀원의 업무 지침은 그대로 둔 채)

## 실습에서 확인하는 것

세 역할을 각각 켜면(기동), 각자 어떤 도구를 쥐고 있는지 화면에서 확인할 수 있습니다. 5교시에서 붙인 플러그인(문서 검색 등)은 **리서처에게만** 가 있는 식이죠. 4교시에서는 "이런 일은 하지 마"라고 **문구로** 막았는데, 여기서는 **애초에 그 도구 자체를 안 쥐여줘서** 확실하게 막습니다.

연구 하나를 맡기면, 로그에 "누가 누구에게 뭘 시켰고, 뭘 받았는지"가 순서대로 남습니다. 여기서 확인할 포인트:

- 아트디렉터가 실행 담당에게 보낸 지시문에, **리서처가 조사한 내용이 실제로 담겨 전달됐는지** (이게 협업의 핵심입니다)
- 각자 자기 역할 밖의 일을 하지 않았는지 (아트디렉터가 직접 계산하지 않았는지 등)

## 이어서 물어보기

한 번 연구가 끝나면, 조건 하나만 바꿔서 "이건 어떻게 되나?"라고 다시 물어볼 수 있습니다. 아트디렉터가 이전 맥락을 기억하고 있어서, 처음부터 다시 조사하지 않고 **바로 재계산만** 시킵니다.

## 정리

- 여러 AI로 나누는 건 "여럿이 좋아서"가 아니라, **역할마다 필요한 정보·도구·권한이 다르기 때문**입니다
- 나눌 이유가 없으면 한 명(하나의 AI)이 더 낫습니다 — 나누면 전달 비용이 생기니까요
- 결과를 볼 때는 "숫자 하나"가 아니라 **최악의 경우·최선의 경우까지 범위로 보는 감각**이 중요합니다

다음 시간부터는 오늘 배운 걸 다 조합해서, 여러분만의 것을 직접 만들어봅니다.
