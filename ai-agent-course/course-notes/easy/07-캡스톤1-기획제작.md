# 7교시 · 캡스톤 1 — 쉬운 설명 버전

## 이제부터는 정해진 문제가 없다

지금까지는 저희가 준비해둔 문서·데이터로 실습했습니다. 여기서부터는 **본인이 원하는 것**을 직접 정해서 만듭니다. 정해진 시간 안에 "일단 동작하는 것"을 하나 완성하는 게 목표입니다.

> 완성도보다 **정상 동작이 먼저**입니다. 크게 벌여놓고 절반만 되는 것보다, 작게 잡아서 끝까지 도는 게 지금은 낫습니다.

## 트랙 고르기

- 오늘 배운 것 중 "이거 내 작업에도 쓰겠는데" 싶었던 순간이 있었다면 → **자유 트랙**
- AI에게 "액션(도구)"을 만들어 쥐여주는 게 재밌었다면 → **트랙 1 (도구 설계)**
- 문서를 정확히 찾아 답하게 만드는 게 재밌었다면 → **트랙 2 (함정 질문 챌린지)**
- 자료를 모아 분석 리포트로 만드는 게 재밌었다면 → **트랙 3 (조사 리포트)**

## 만들기 전에 Claude Code(코치)에게 먼저 점검받기

바로 만들기 시작하고 싶겠지만, 5~10분만 점검에 씁니다. 아래처럼 물어보세요.

```
내 캡스톤 주제를 알려줄게. 만들기 전에 아래를 점검해줘.

주제: [한 줄]
만들고 싶은 것: [화면에 뭐가 보여야 하는지, 최대한 구체적으로]

① 범위 — 오늘 안에 혼자 만들 수 있는 크기인가? 너무 크면 어디를 잘라야 하는지 알려줘.
② 기술 매핑 — RAG·도구·플러그인 연결·여러 AI 협업 중 무엇을 쓰게 되나?
③ 데이터 — 어떤 데이터가 필요하고, 없는 건 가상으로 만들어줄 수 있나?
④ 입력 점검 — 내 설명에 회사 기밀 등 민감한 정보가 섞여 있으면 짚어주고
   가상 버전으로 바꿔 제안해줘.
```

디자인 작업으로 치면 "이 컨셉, 오늘 안에 완성 가능한 볼륨일까요?"를 미리 물어보는 것과 같습니다.

## 마감 전에 확인할 것

- [ ] 무엇을 만들지, 범위를 얼마나 줄였는지 확정했다
- [ ] 원본 앱은 그대로 두고, 복사한 폴더에서 작업했다 (되돌릴 자리 확보)
- [ ] 완성도는 낮아도 **실제로 끝까지 동작**하는 결과물이 있다
- [ ] (도구 설계·문서 질답 트랙이라면) 손대기 전과 후를 비교한 기록이 있다

## 정리

오늘 배운 것들이 실제로는 이렇게 깔끔하게 나뉘어 있지 않다는 걸 만들면서 알게 되실 거예요. 그걸 확인하는 것까지가 이번 시간의 진짜 목표입니다.
