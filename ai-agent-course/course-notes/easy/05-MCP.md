# 5교시 · MCP — 쉬운 설명 버전

## 문제: 액션(도구)이 20개, 30개면?

4교시에서 도구 하나 붙이는 데도 손이 꽤 갔죠. 실무에선 필요한 기능이 3~4개로 끝나지 않습니다. 그때마다 처음부터 다 만들어 연결해야 한다면 너무 번거롭겠죠. **연결하는 방법 자체를 하나의 규격으로 통일**하면 어떨까요 — 이게 MCP입니다.

## MCP를 디자이너의 말로 옮기면 — "플러그인 설치 표준"

포토샵에 서드파티 플러그인(익스텐션)을 설치하는 걸 떠올려보세요. 누가 만들었든, 어떤 기능이든, **설치 방법은 항상 똑같습니다.** 목록에서 고르고 설치 버튼만 누르면 끝이죠.

MCP도 똑같습니다. 서버(플러그인 제공자)가 "나는 이런 기능을 제공해요"라고 먼저 알려주면, 내 AI 프로그램(Host)이 그 목록을 받아서 **기존 도구 목록에 그대로 추가**합니다. 그다음부터 AI는 4교시에서 배운 것과 똑같은 방식으로 — 설명문만 보고 — 어떤 도구를 쓸지 고릅니다.

## 실습으로 확인하는 것

1. **연결 전** — 사내 자료에 대해 물어봐도 AI가 답을 못합니다 (관련 도구가 없으니까)
2. **[연결] 버튼 클릭** — 서버 하나를 붙이면, 도구 목록에 새 기능이 추가됩니다
3. **같은 질문 재시도** — 이제 답을 할 수 있습니다

## 두 가지 다른 성격의 플러그인

- **내 컴퓨터에서 도는 플러그인** (로컬 서버) — 인터넷 없어도 동작. 우리가 직접 만든 것.
- **인터넷 저편에 있는 플러그인** (원격 서버, 예: Microsoft Learn 문서 검색) — 남이 만들어서 운영 중인 것. 내부를 볼 수 없어도 **설치 절차는 똑같이 버튼 하나**입니다.

## API 키가 필요한 플러그인도 있다

Tavily(웹 검색 서버)처럼 유료/가입이 필요한 플러그인은 1교시에서 배운 API 키가 여기서도 똑같이 필요합니다. 키를 발급받아 `.env` 서랍에 넣어두면 됩니다.

## 붙이면 곧 능력이 된다 — 주의할 점

연결한 순간 AI가 할 수 있는 일이 늘어납니다. 오늘 붙인 플러그인들은 "읽기"만 하지만, **삭제하거나 수정하는 플러그인도 똑같이 버튼 하나로 붙습니다.** 그래서 낯선 플러그인을 연결하기 전엔 "이게 뭘 할 수 있는지" 확인하는 습관이 중요합니다.

행동을 막는 방법은 두 겹입니다.

- **문구로 막기** (4교시에서 배운 역할 프롬프트) — 편하지만 표현 바꾸면 뚫릴 수 있음
- **아예 연결을 안 하기** — 연결 안 된 플러그인은 애초에 목록에 없으니 AI가 쓸 수 없음. 더 확실함

## 정리

- 플러그인 제공자(서버)는 "나 이런 거 할 수 있어요"라고 먼저 광고하고, 내 AI는 그걸 받아서 도구 목록에 합칩니다
- 내가 만든 것이든 남이 만든 것이든, **붙이는 절차는 항상 같습니다** (버튼 하나)
- 연결 = 능력이므로, 무엇을 연결하는지가 곧 권한 문제입니다
