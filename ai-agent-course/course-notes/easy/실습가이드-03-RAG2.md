# 실습 가이드 3 · RAG 2 — 검색 실패 진단과 처방 (쉬운 설명 버전)

목표: "증상 확인 → 원인 찾기 → 처방 → 진짜 나아졌는지 재확인" 순서를 직접 실행해봅니다. 02에서 만든 `rag-lab` 폴더를 이어서 사용.

원본은 [학습노트 03(쉬운 설명)](../03-RAG2-검색개선.md) 참고.

## 체크리스트

### 1. 증상 확인 (02 마지막에 기록해둔 것부터)
- [ ] 02-4단계에서 발견한 "답이 흔들리는" 질문을 다시 던져 답변과 근거 5개를 원문과 대조
- [ ] 판별: 근거 조각 안에 답변 내용이 실제로 있는가? → 있으면 "검색이 애매한 걸 골라온 문제", 없으면 "AI가 요약을 잘못한 문제"

### 2. Reranking (2차 심사) 붙이기
```
검색에 Reranking 을 추가해 줘.
- 재정렬을 켜고 끌 수 있는 토글을 만들어 줘.
- 1차 검색으로 후보 10개를 꺼내고, 그 후보를 질문과 함께 LLM 에 넘겨 다시 순서를 매겨 줘.
- 재정렬 결과 상위 5개를 답변 생성의 근거로 써 줘.
- 재정렬에 걸린 시간을 화면에 표시해 줘.
```
(서버 재시작) 토글 켜고/끄고 같은 질문 비교 → 답변, 근거, 걸린 시간 기록

### 3. Metadata Filter (태그로 미리 거르기) 붙이기
```
검색에 문서 단위 필터를 추가해 줘.
- 적재된 문서 목록을 화면에 보여주고, 체크박스로 검색 대상을 고를 수 있게 해 줘.
- 고른 문서 안에서만 검색이 일어나게 해 줘.
- 아무것도 고르지 않으면 전체를 대상으로 해 줘.
```
(서버 재시작) 같은 질문을 "필터 없음" / "문서 A만" / "문서 B만" 세 조건으로 비교

### 4. 처방 비교 정리
- [ ] Reranking이 고친 것 vs Metadata Filter가 고친 것을 한 문장씩 적어보기
- [ ] 02에서 발견한 증상에는 어느 처방이 맞았는지 결론 내기

### 5. Query Rewrite (검색어 다시 쓰기) 붙이기 — 짧은 검색어 문제
- [ ] 02에서 단어 검색(숫자·한 단어짜리 질문)이 헛돌았던 사례가 있으면 재확인, 없으면 새로 시도
```
검색 전에 질의를 다시 쓰는 단계를 추가해 줘.
- 사용자가 넣은 질의를 LLM 에 넘겨 검색에 맞는 형태로 바꾸고, 바뀐 질의로 검색해 줘.
- 원래 질의와 다시 쓴 질의를 화면에 나란히 보여 줘.
- 이 단계를 켜고 끌 수 있는 토글을 만들어 줘.
```
개선(저장소 맥락을 미리 알려주기):
```
질의 재작성 프롬프트를 고쳐 줘.
- 저장소에 적재된 문서 목록을 프롬프트에 넣어 줘.
- 그 문서들의 맥락 안에서 질의를 해석하도록 지시해 줘.
- 저장소 밖의 뜻으로 넓히지 말라고 명시해 줘.
```

### 6. 자동 채점 (AI에게 채점까지 시키기)
- [ ] 본인 문서에 대한 질문-정답 5개를 직접 만들어 `grading.json`(채점용 답안지 파일) 형태로 정리
```json
[
  {"q": "질문1", "expected": "기대하는 답의 핵심 요소"},
  {"q": "질문2", "expected": "..."}
]
```
```
답변 품질을 채점하는 기능을 추가해 줘.
- grading.json 을 읽어서, 각 질문을 앱에 던지고 답변을 받아 줘.
- 그 답변을 기대하는 답과 비교해 1~5점으로 채점하고 이유를 한 줄로 적게 해 줘.
- 결과를 표로 보여주고 평균 점수를 계산해 줘.
```
- [ ] 조건별(무처방/필터만/재작성만/재정렬만/셋다)로 라운드를 돌려 평균 점수·시간 기록
  ```
  라운드 0 (기준선): 평균 ___점
  라운드 1 (Reranking): 평균 ___점
  라운드 2 (Metadata Filter): 평균 ___점
  라운드 3 (Query Rewrite): 평균 ___점
  라운드 4 (셋 다): 평균 ___점
  ```
- [ ] 점수가 이상한 문항 1~2개는 사람이 직접 원문 대조 (채점하는 AI도 가끔 틀립니다)
