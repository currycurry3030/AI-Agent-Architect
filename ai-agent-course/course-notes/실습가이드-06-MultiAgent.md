# 실습 가이드 6 · Multi-Agent — 역할을 나눠 연구를 맡긴다

목표: 연구책임자·자료조사·실험수행 세 역할이 서로 다른 도구/지시로 협업하는 걸 직접 돌려보고, 왜 나누는지 체감한다. 05에서 만든 `agent-lab`을 이어서 사용.

원본은 [학습노트 06](06-MultiAgent.md) 참고.

## 체크리스트

### 1. 가상 데이터 CSV 준비
본인 관심 주제로 간단한 시뮬레이션 데이터를 만듭니다. 예: 신제품 출시 후 24개월 손익, 마케팅 예산 대비 매출, 재고 회전율 등. Claude Code에게 바로 만들어 달라고 해도 됩니다.
```
data/research/scenario.csv 파일을 만들어줘. 주제는 [본인 주제 한 줄].
변수마다 값의 형태를 다르게 넣어줘 — 단일값 하나, 최소/기준/최대 3개짜리, 평균/표준편차 2개짜리를 섞어서.
그리고 "값"이 아니라 "계산 방식"을 설명하는 행도 1~2개 넣어줘 (예: 확률변수를 어떻게 뽑을지, 월별로 어떻게 변화하는지).
```

### 2. Multi-Agent 구조 추가
```
이 앱에 Multi-Agent 연구 모드를 추가해줘. [에이전트] 탭을 새로 만들어줘.

- 연구책임자(director), 자료조사 연구원(researcher), 실험수행 연구원(experimenter) 세 역할을 각각
  별도 프로세스(로컬 서버)로 띄우고, [프로세스] 카드에서 각각 [기동] 버튼으로 켤 수 있게 해줘.
  각 프로세스가 뜨면 PID와 포트를 보여줘.
- 연구책임자만 사용자와 대화한다. 연구책임자는 직접 조사하거나 코드를 실행하지 않고,
  자료조사 연구원과 실험수행 연구원에게 일을 위임하고 결과를 받아 다음 지시를 정한다.
- 자료조사 연구원은 doc_search 같은 MCP 문서 검색 도구만 가지고, 분석 방법을 설계한다.
  코드를 짜거나 실행하지 않는다.
- 실험수행 연구원은 파이썬 코드 실행 도구만 가지고, 넘겨받은 설계를 바탕으로 실제로 코드를 돌려
  수치를 낸다. 정량 결과는 실제 코드 실행 결과만 사용한다. 판단(결론)을 내리지 않는다.
- 두 연구원은 서로를 직접 부를 수 없고, 모든 전달은 연구책임자를 거친다.
- 화면에 "연구 시작" 입력창과 [맡기기] 버튼, 그리고 "Agent 간에 주고받은 정보" 로그를 시간순으로
  보여줘 (연구책임자가 맡긴 것 = 파란 상자, 연구원이 돌려준 것 = 회색 상자).
- 같은 세션에서 "이어서 물어보기"가 가능하게 해줘 (연구책임자가 이전 연구를 기억).
- [프로세스] 카드에 각 역할이 지금 쥐고 있는 도구 목록도 보여줘.
```
(서버 재시작 후) `[에이전트]` 탭에서 자료조사·실험수행 각각 `[기동]`

### 3. 도구 분리 확인
- [ ] 세 역할의 도구 목록을 나란히 읽고, 05에서 붙인 MCP 도구(자료 조사 서버 등)가 어느 역할에게 갔는지 확인

### 4. 동작 확인용 간단 연구
```
동전을 10번 던져 앞면이 6번 이상 나올 확률을 구하려고 합니다.
어떤 방법으로 구할 수 있는지 조사하고, 파이썬으로 실행해 확인하세요.
정량 결과는 실제 코드 실행 결과를 사용하세요.
```

### 5. 본 실습 — 본인 시나리오 연구
- [ ] `scenario.csv`를 근거로 연구 질문 작성 (수치로 답이 나오는 질문으로 좁히기)
- [ ] "연구 시작"에 붙여넣고 `[맡기기]`
- [ ] 로그를 위에서부터 읽으며 확인:
  - [ ] 자료조사 연구원이 무엇을 읽고 무엇을 설계했는지
  - [ ] 연구책임자가 실험수행 연구원에게 보낸 지시문에 앞 단계 결과가 실렸는지
  - [ ] 실험수행 연구원이 실제로 실행한 코드와 출력
  - [ ] 각 역할이 자기 역할 밖의 일(계산·판단 등)을 하지 않았는지

### 6. 이어서 물어보기
- [ ] 조건 하나를 바꿔 재질문 (예: "○○ 조건이 이렇게 바뀌면 어떻게 되나? 나머지는 그대로 두고 다시 계산해줘")
- [ ] `[새 연구로 시작]`은 누르지 않기 (기억이 지워짐)
- [ ] 수치가 어느 방향으로 움직였는지, 4번과 비교해 기록
