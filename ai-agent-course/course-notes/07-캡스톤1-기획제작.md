지금까지는 전부 준비된 문제였다. 여기서부터 100분은 **본인 업무에서 문제를 가져오거나, 출제된 문제를 내 시스템으로 푸는** 시간.

## 공통 규칙
- 시작할 때 앱 폴더를 `capstone` 안으로 **복사**해서 작업 (원본은 그대로 둠 — 되돌릴 자리 확보). 예: `rag-lab` → `capstone\rag-lab`
- 챌린지 트랙(1·2) 공통: **질문 문구는 고치지 않음**, 결과값 하드코딩 금지, 특정 문항만 통과시키는 예외 처리 금지 (결과 페이지에서 확인 대상)
- 문서·데이터는 공개 자료 또는 가상 자료만 (7-4번 점검 반영)

## 트랙 1 — 도구 설계 (agent-lab)
4교시를 본인 업무로 확장. 도구 묶음 전체를 시나리오로 교체.
1. **시나리오 한 줄** (예: 설비 점검 이력을 조회·등록하고, 점검 주기를 바꾸고, 지연 건을 집계한다)
2. **도구 3종 이상 설계** — 이름·설명문·인자·동작을 표로 먼저 작성. 4교시 원칙 준수: 판단 근거는 설명문, 도구 간 인자 구조가 신호가 되지 않게(다 똑같은 인자 구조로).
3. **데이터 파일 설계** — 도구가 읽고 쓸 JSON/CSV를 가상 수치로 (`data/notes.json` 견본 참고)
4. **Claude Code로 구현** — `lab/tools.py`에 추가·교체, 재시작해야 반영
5. **질문 10개 확정** — 조회·등록·수정·집계 섞고, 두 도구에 걸릴 법한 애매한 질문도 2개 정도 포함. 이게 라운드 기록의 문항.
6. **라운드 돌리기** — 10개 차례로 던져 도구·인자 확인. 틀린 문항은 **설명문과 데이터만** 수정해 재시도 (도구 코드 변경은 라운드 사이가 아니라 설계 단계의 일).

**성공 기준: 10문항 중 8개 이상**

## 트랙 2 — 함정 질문 챌린지 (rag-lab)
실제 상금 1,000만원 AI 경진대회의 문제 유형(표 속 숨은 정답, 유사 항목 혼동, 조각 경계에 걸친 답)을 반영해 「2026년 6월 소비자물가동향」(국가데이터처)에서 5문항 출제.

**미션**: 5문항 중 4개 이상에서 **답 정합**(핵심 요소 빠짐없이·오류 없음)과 **근거 정합**(표시된 근거 청크에 정답 내용이 실제로 있어야 함)을 동시에 만족.

**특별 판정**: 환각 유도 문항은 "문서에서 확인되지 않습니다" 계열 답이 통과 / 이중 기준 문항은 두 기준을 구분해 답하면 통과(한 값만 단정 시 어느 기준인지 명시해야 통과).

**허용 수단**: 청킹 전략 교체+재적재, K값 조정, 답변 프롬프트 강화(근거 제한·인용·표 처리 지시), 파싱 보강, 검색 방식 점검·조정.

**반칙 3가지**
1. 질문 문구를 바꾸는 것 (토씨 하나도 그대로 입력, 고칠 대상은 시스템)
2. 앱 안에 정답을 심는 것 (프롬프트/코드/설정/적재문서 어디에도 정답 힌트 금지 — **다만 정답을 놓고 AI와 논의하는 것 자체는 반칙 아님**)
3. 문항 전용 분기("이 질문이 오면 이렇게 답하라") 금지 — 비슷한 다른 질문에도 통하는 일반적 개선만 인정

> 💬 **정답을 AI와 논의하는 것은 반칙이 아니다** — ChatGPT/Claude/Gemini 같은 대화형 AI에는 문항·정답·우리 시스템 답과 근거까지 다 보여주고 "왜 틀렸는가, 어디를 고쳐야 하는가" 논의해도 됨 (이들은 앱을 못 고치므로). **다만 Claude Code에게는 정답을 주지 않는다** — 앱을 직접 고치는 도구라서 정답을 알면 정답 처리 코드/프롬프트가 만들어질 위험(=반칙 2·3). Claude Code에는 **증상까지만** 전달: 예) "문항 3에서 하락 부문이 두 개만 나온다. 근거 청크를 보니 문단이 중간에서 끊겨 있다."
> 기준: "이 질문이 오면 교통 -0.6%라고 답해"=반칙 / "청크가 문장을 중간에서 자르지 않게 문단 기준으로 바꿔줘"=개선.

**사전 준비**: rag-lab 사본에서 [초기화]로 2·3교시 문서 비우기 → PDF 업로드→청킹→적재 → 청크 수 0 아닌지 확인 → 답변생성 켜고 가벼운 질문으로 근거 번호 확인.

**5문항 요지**
1. 표 속 정답: 석유류 전년동월대비(정답 24.7%) — 표가 파싱에서 무너지면 이웃 숫자(휘발유23.1/경유33.7/등유23.1)가 답으로 올라옴
2. 유사 항목 혼동: 농산물및석유류제외지수(정답 2.4%) — 식료품및에너지제외지수(2.5%)와 항상 붙어다녀 혼동 유발
3. 조각 경계: 하락 부문 3곳+수치(교통-0.6%, 오락문화-0.2%, 통신-0.1%) — 문단 끝에 몰려있어 청크가 문장을 자르면 반쪽 답
4. 이중 기준: 기준연도(지수=2020년 / 가중치=2022년, 두 기준 구분해야 통과) — 부록엔 2020년만 다시 나와 단정 유도
5. 환각 유도: 체감물가상승률 → 정답은 "확인되지 않음" — "체감물가"라는 단어는 실재, 생활물가지수(3.4%)를 체감물가상승률로 둔갑시키기 쉬움

**진행**: 아무 처방 없이 먼저 돌려 **라운드 0** 기록 → 틀린 문항의 근거 청크를 열어 원인을 가른 뒤 하나씩 고침.

## 트랙 3 — 조사 리포트 (agent-lab, run6)
6교시 구조(연구책임자·자료조사·실험수행)는 그대로, 재료 3가지만 교체.
1. **연구 질문 한 줄** — 수치로 답이 나오는 질문으로 좁힘 (예: "이 조건이 흔들리면 무엇이 결과를 지배하는가")
2. **데이터 CSV** — `data/research/`에 가상 수치 (`line_transition.csv` 견본처럼 단일값/최소-기준-최대/평균-표준편차 등 제공형태를 섞고, **값이 아니라 방식을 적는 행**(산식, 확률변수 추출 방식)을 넣으면 결과가 안정됨)
3. **참고 문서** — `mcp-servers/doc-search/docs/`에 조사 담당이 읽을 md 문서 추가 후 서버 재연결 (없으면 조사 담당이 웹으로 감)
4. **연구 실행** — `run6.bat`으로 켜고 질문 위임. 6교시처럼 지시문에 앞 단계 결과가 실렸는지, 역할을 지켰는지, 수치가 모순 없는지 확인
5. **후속 질의** — 조건 하나 바꿔 재위임, 결과 변화 방향을 리포트에 기록
6. **리포트 정리** — 최종 결론(분포·민감도)과 로그 근거를 결과 페이지에 옮김

## 라운드 기록 (개선 여부를 숫자로)
3교시의 원칙(라운드 0 = 손대기 전 기준선 필수, 한 번에 한 가지만 변경) 그대로 적용.
```
라운드 0 (기준선): 통과 수 ___/___  실패 문항과 증상(A/B/C): ___
라운드 1 (처방: ______): 통과 수 ___/___
라운드 2 (처방: ______): 통과 수 ___/___
```
분모: 트랙1=10개, 트랙2=5개. 트랙3/자유트랙은 "실행이 끝까지 돌았는가 / 수치가 모순 없는가"를 라운드마다 기록.

실패 문항 분류: **A(검색·선택 오류)** 관련없는 정보/엉뚱한 도구 / **B(형식 오류)** 정보는 맞는데 출력 형식 문제 / **C(지시 오류)** 근거 부족한데 답을 지어냄.
