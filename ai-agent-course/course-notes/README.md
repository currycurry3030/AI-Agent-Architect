## 반복해서 등장하는 핵심 원칙 (전 교시 공통)

1. **`.env`는 Git 유출 방지용이지, Claude Code(Agent)로부터 Key를 숨기는 장치가 아니다.**
   Agent가 파일·셸에 접근 가능하면 Key를 읽을 수 있다.
2. **LLM은 도구 "선택"만 한다. 실행은 앱(코드)이 한다.** AI는 도구의 설명문(description)만 보고 판단하며 코드는 못 본다 → 설명문 품질이 곧 정확도.
3. **행동 범위는 두 겹으로 막는다**: ① 역할 프롬프트(문구, 뚫릴 수 있음) ② 아예 도구를 안 쥐여주기(확실함, MCP 연결/해제·Multi-Agent 역할분리로 구현).
4. **RAG 답변 품질 = 검색 품질.** 문서가 수천 쪽이어도 AI가 실제로 읽는 건 검색이 골라낸 몇 조각뿐.
5. **"고치는 순서"는 시스템 불문 공통 기술**: 증상 확인 → 원인(생성 vs 검색?) 분리 → 맞는 처방 선택 → 개선 여부를 반드시 숫자로 재확인(라운드 0 기준선 필수, 한 번에 한 가지만 변경).
6. **Multi-Agent로 나누는 이유는 "여러 개가 좋아서"가 아니라 역할마다 필요한 자료·도구·권한이 달라서.** 나눌 이유 없으면 한 Agent가 낫다(통신 비용 발생).
